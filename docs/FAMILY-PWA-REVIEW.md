# SpaceOps 가족용 PWA 검토본

## 실제 상태
기존 Next.js 16 / React 19 / Supabase Auth + Postgres + private Storage 유지.
GitHub: acesstory-kr/spaceops, 개발 브랜치 feature/family-pwa.
운영은 main이며 이번 검토에서는 main, 운영 DB 구조와 기록을 변경하지 않음.
복귀 기준 커밋: 30e883adfb8edf340fed64d7d4006ee8b35b032a.
기존 운영 배포: dpl_NS5mKB6Hy7pZvUebQxFHwgj5qd6m.

## 구현된 변경
- manifest, 192/512/180 아이콘, maskable 아이콘, standalone 설정, safe-area.
- iPhone/Android 설치 안내 /install. Android 설치 이벤트가 지원되면 설치 버튼.
- 기본 진입은 오늘의 업무. 전체/완료/진행 중/미완료 요약, 하단 탐색과 더보기.
- 화면 선택을 sessionStorage에 저장. 업무/사진/인증 데이터는 저장하지 않음.
- 공개 정적 파일만 서비스 워커 캐싱. 새 버전은 사용자가 저장 후 적용.
- 끊어진 연결은 안내 화면으로 이동. 열린 화면의 업무는 메모리에서만 유지되고 새로고침하면 제거.
- 온라인 10초 폴링과 앱 복귀 갱신. 보이는 앱의 변경 알림은 메모리 기반이며 푸시가 아님.
- 기본 완료 동작에 서버 시각 completedAt 기록, 개별 편집에 최근 100건 필드명 변경 이력.
- 상태 미진행/진행중/완료/일정 변경/보류. 일정생략 없음.
- 촬영 입력 추가. 기존 여러 장 업로드/개별 선택 삭제 유지.
- preview에서 운영 API 쓰기 차단, DB 트랜잭션 READ ONLY, 스키마 자동 초기화 중지.

## 유지
월간/주간 업무, 반복 생성/범위 수정, 주간점검/템플릿, 인건비, iCal 취소/변경/중복방지,
혜화/상수 짧은 명칭, 상수 15시 입실 체크, 메모 6줄 자연 높이, 사진 비공개 저장.

## 미완료 — 후속 승인 및 개발 필요
이 검토본은 아래 항목을 구현 완료한 전체 요청서 버전이 아님.
- 역할별 관리자/담당자/조회자와 관리자 초대·권한 UI. 현재는 기존 허용 이메일 모두 공동 업무 편집 가능.
- 사용자 배정은 현재 이름 표시이며 보안 역할이 아님. 고유 계정 배정으로 전환 필요.
- 임의 공간 추가/수정과 공간 종합 화면. 현재 6공간+개인 카테고리 고정.
- 사진 청소 전후의 영구 분류, 업로드/촬영 시각, 압축 및 실패 파일 재시도 큐.
  현재 전후 버튼은 같은 업무에 업로드하며 분류 메타데이터가 저장되지 않음.
- 백그라운드 웹 푸시, 서버 알림함, 긴급도, 미완료 자동 알림.
- 폴링을 통한 최대 약10초 갱신이며 WebSocket 실시간 연결은 아님.
- 일괄 변경과 iCal 자동 변경의 영구 감사 이력. 현재 개별 저장만 최근100건.
- 완료 시간이 과거 기록에는 없음. 기존 완료 기록에 시각을 임의 생성하지 않음.
- 관리자가 매주 항목 추가/수정/삭제 가능하나 새로운 권장 항목을 기존 데이터에 자동 주입하지 않음.
- 외부 예약 자체를 별도 reservation 데이터로 표시하는 UI와 밍글룸 공급자 연동.
  현재 iCal URL 검증은 Airbnb 허용 도메인에 한정. 무조건 모든 외부URL 허용하지 않음.
- Vercel Cron 주기 실행 구성과 전용 비밀키. 현재 수동 동기화 유지.

migrations/001-family-proposal.sql은 검토용 초안이고 실행하지 않음. 적용 전 계정 역할 매핑,
DB 백업, 테스트 DB 검증, 서버 측 RBAC 전체 경로 검증이 필요함.
운영 배포 승인과 DB 변경 승인은 별개임. 이 초안만 적용해도 권한 기능이 생기는 것은 아님.

## 가족 계정
기존 허용 이메일을 Supabase Auth로 로그인하는 구조 유지. 새 계정 등록은 Supabase Auth에
사용자를 초대하고 Vercel ALLOWED_EMAILS에 허용해야 함. 초대 메일 발송은 별도 요청 필요.
비밀번호를 공유하지 말고 각 계정을 사용. 이번 작업에서 새 가족을 초대하거나 기존 권한을 바꾸지 않음.

## 저장과 보안
Postgres spaceops 스키마에 업무/점검/연동정보/정산. photos 테이블에 파일 참조,
spaceops-photos 비공개 Storage에 사진 원본. POSTGRES_URL, SUPABASE_SERVICE_ROLE_KEY는 서버 전용.
iCal URL은 서버 DB에 저장, GET 목록에는 노출하지 않음. 브라우저에서 직접 DB 접근하지 않음.
private 업무는 작성자만 조회/수정. 기존 공동 업무는 허용 계정 모두 편집 가능.
서비스 워커는 /api, /auth, 로그인, 비밀번호, RSC를 캐시하지 않음. 오프라인 쓰기 큐 없음.

## 설치와 실기기 확인
1. iPhone Safari로 검토 URL 열기 → 공유 → 홈 화면에 추가 → 홈 아이콘 실행.
2. Android Chrome으로 열기 → 앱 설치 또는 메뉴의 홈 화면에 추가 → 아이콘 실행.
3. 브라우저 주소창이 없는지, 상하 안전영역, 하단 메뉴, 달력/주간업무/메모/사진 확인.
4. 검토본 API 쓰기는 차단됨. 운영 승인 전 실제 기록 수정 테스트를 하지 말 것.
5. 비행기 모드 → 새로 열어 오프라인 안내 표시 → 온라인으로 복귀 후 다시 연결.
6. 두 가족 계정 로그인·서로 다른 기기에서 반영·카메라 권한·iOS 설치는 실제 기기로 별도 검증.
7. PWA 업데이트 안내 후 저장 → 새 버전 적용. 작성 중 내용을 자동으로 새로고침하지 않음.
8. 보호된 Vercel preview는 Vercel 인증이 필요할 수 있음. 운영 도메인 설치는 최종 승인 후 가능.

## Capacitor
현재 Next.js 서버 API와 쿠키 인증에 의존하므로 output:export를 켜서 그대로 패키징할 수 없음.
1차 선택: HTTPS 웹을 PWA로 안정화. 이후 별도 모바일 셸 + 동일 서버 API 구조.
네이티브 셸은 capacitor://localhost 출처, 쿠키 SameSite, CSRF 허용 출처,
PKCE deep link, 카메라 어댑터, 토큰 보관을 별도 설계/검증해야 함.
현재 proxy는 동일 출처 API만 허용하므로 이를 무조건 완화하면 안 됨.
스토어 등록/서명키/개발자 계정 생성/결제는 이번 범위에서 실행하지 않음.

## 운영과 비용
새 유료 서비스 가입 없음. 기존 Vercel/Supabase 요금제 유지.
사진 원본 저장 용량·다운로드 트래픽, 동시접속 폴링 API/DB 사용량을 확인해야 함.
10초 폴링은 보이는 탭에서만 실행되지만 기존30초보다 요청량 증가.
푸시는 VAPID 키 관리/구독 정리/발송 재시도 및 동의 처리가 추가로 필요함.
실제 비용은 사용량·현재 요금제에 따라 달라 숫자를 확정하지 않음.
